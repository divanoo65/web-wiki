**长期运行代理面临上下文断层的挑战**
由于上下文窗口限制，代理在离散会话间无法保持记忆，导致其在处理复杂任务时容易出现重复劳动或进度丢失。

**采用“初始化代理”与“编码代理”的双重架构**
通过专门的初始化代理构建环境脚手架，配合后续编码代理进行增量开发，能有效解决代理一次性完成任务失败的问题。

**利用结构化文件实现状态持久化**
通过 `claude-progress.txt`（进度追踪）、功能列表 JSON 文件及 Git 历史记录，为代理提供清晰的上下文，确保其在每个新会话中能准确理解当前工作状态。

**强制执行增量开发与整洁状态管理**
要求代理一次仅处理一个功能，并在会话结束时提交代码并更新进度，确保代码库始终处于可交付的整洁状态。

**引入端到端测试工具以验证功能完整性**
仅靠代码分析不足以确保功能实现，必须为代理配备浏览器自动化工具（如 Puppeteer），使其能像人类一样验证端到端的功能表现。
