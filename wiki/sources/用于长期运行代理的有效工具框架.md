# 用于长期运行代理的有效工具框架

## 执行摘要
随着 AI 代理承担的任务日益复杂，如何在有限的上下文窗口内实现长周期的任务交付成为核心瓶颈。Anthropic 通过研究发现，仅靠上下文压缩不足以支撑复杂项目的完整开发。本文提出了一种基于“初始化代理”与“编码代理”的协作框架，通过结构化的进度追踪（`claude-progress.txt`）、Git 版本控制以及功能清单（Feature List）管理，确保代理在离散的会话中能够保持连贯的开发状态，从而实现生产级的应用构建。

## 核心要点

长期运行的 AI 代理在处理复杂任务时，常面临“上下文遗忘”和“任务执行偏差”两大难题。当代理在多个会话间切换时，由于缺乏对前序工作的准确认知，往往会陷入重复劳动或因上下文耗尽而导致项目中断。

为了解决这些问题，该框架引入了以下关键机制：

1. **双重代理架构**：
   - **初始化代理（Initializer Agent）**：负责项目的顶层设计，创建 `init.sh` 环境脚本、初始化 Git 仓库，并生成包含所有待办功能的 JSON 进度清单。这一步为后续工作奠定了明确的“脚手架”。
   - **编码代理（Coder Agent）**：在后续会话中，该代理被强制要求执行增量式开发。通过读取进度清单，它每次仅处理一个功能点，并在会话结束时将代码库恢复至“整洁状态”（即通过测试、可合并的代码）。

2. **结构化状态管理**：
   - 放弃了单纯依赖模型记忆的做法，转而使用 `claude-progress.txt` 和 Git 历史作为“外部记忆”。这种做法模拟了人类工程师的协作模式，使代理能够通过查看提交记录和进度文件，快速恢复工作上下文。
   - 使用 JSON 格式管理功能列表，防止模型在编辑过程中意外破坏文档结构，确保了任务执行的确定性。

3. **端到端测试闭环**：
   - 代理的失败往往源于“自以为完成”的错觉。通过集成浏览器自动化工具（如 Puppeteer MCP），代理能够像人类用户一样进行端到端测试。这种实证反馈机制显著降低了代码逻辑正确但功能无法实际运行的风险。

通过这些工程化手段，开发者可以将复杂的长周期任务拆解为可控的增量步骤，使 Claude 等前沿模型能够更稳定地完成从原型到生产级应用的构建过程。
