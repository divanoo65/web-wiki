## 执行摘要

随着 AI 代理能力的增强，开发者越来越多地要求它们承担需要数小时甚至数天才能完成的复杂任务。然而，代理必须在离散的会话中工作，每个新会话开始时对之前发生的事情一无所知，这类似于轮班工程师交接项目。Anthropic 在其 Claude Agent SDK 中发现，仅靠压缩等上下文管理功能不足以让代理跨多个上下文窗口持续有效工作。两种典型失败模式是：代理试图一次性完成整个应用而耗尽上下文；或是在项目后期看到部分进展便过早宣布完成。为解决这些问题，Anthropic 开发了一个包含 **初始化代理** 和 **编码代理** 的双重框架。初始化代理负责设置环境：编写功能需求文件、初始化脚本 `init.sh`、工作日志 `claude-progress.txt` 和初始 git 提交。编码代理则在每个会话中仅处理一个功能，取得增量进展后留下结构化更新（如提交带描述信息的 git 提交、更新进度文件）。此外，通过提供浏览器自动化工具（如 Puppeteer MCP），代理可以像人类用户一样进行端到端测试，显著提高了验证功能完整性的能力。该框架使代理能够像优秀软件工程师一样逐步构建复杂应用，并保持代码库的整洁与可交付状态。

## 核心要点

1. **长期运行代理的核心挑战**：代理必须在有限上下文窗口内工作，每次新会话开始对之前一无所知。仅靠压缩无法弥合编码会话之间的鸿沟，模型倾向于“一键完成”或过早满足于已有进展。这要求一种显式的跨会话状态传递机制。

2. **双重解决方案**：第一轮使用“初始化代理”设置完整环境，后续每轮使用“编码代理”取得增量进展。初始化代理负责生成超过 200 个功能条目的 JSON 需求文件（如“新聊天按钮创建对话”），所有功能初始标记为 `passes: false`，以清晰展示完整目标。编码代理被严格禁止删除或修改功能条目，只能更改 `passes` 字段状态，从而避免功能遗漏。

3. **增量进展与整洁状态**：编码代理一次只处理一个功能。每完成一个功能必须提交到 git，附带描述性提交信息，并在 `claude-progress.txt` 中编写进展摘要。这种方式使得后续代理可以通过 git 历史和工作日志快速理解当前状态，甚至能利用 git 撤销糟糕的更改恢复代码库工作状态，避免重复猜测和修复。

4. **端到端测试的必要性**：未受引导的 Claude 倾向于仅通过代码检查或单元测试就判定功能完成，而忽略端到端问题。引入浏览器自动化工具（Puppeteer MCP）后，代理能够像真实用户一样操作界面并捕获视觉或交互错误，如浏览器原生警告模态框无法被 Puppeteer 感知等局限性仍需注意。

5. **关键组件设计**：环境脚手架包括 `init.sh`（一键环境配置）、`claude-progress.txt`（持续记录进展）、严格结构的 JSON 功能列表（避免模型随意修改）以及 git 版本控制。这些设计灵感来源于优秀工程师日常工作中的清晰任务规划、文档记录和版本管理习惯。

6. **实用价值**：该框架已被集成到 Claude Agent SDK 中，成为多上下文工作流的最佳实践。开发者只需为首次会话提供差异化提示词，随后的代理即能像“轮班工程师”一样高效接力协作，大幅提升长期复杂任务的完成质量与效率。
