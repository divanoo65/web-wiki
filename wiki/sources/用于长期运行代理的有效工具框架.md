# 用于长期运行代理的有效工具框架

## 执行摘要
随着 AI 代理（Agent）处理复杂任务的需求增加，如何在有限的上下文窗口（context window）内实现跨会话的持续进展成为核心挑战。Anthropic 通过 Claude Agent SDK 提出了一种结构化的解决方案：通过“初始化代理”建立环境脚手架，并利用“编码代理”进行增量式开发。该方法通过引入进度追踪文件、Git 版本控制及端到端测试，有效解决了代理在长期任务中常见的“一次性完成过多任务”或“过早宣布任务完成”的失败模式。

## 核心要点

### 1. 长期运行代理的挑战
AI 代理在处理复杂项目时，往往受限于上下文窗口的容量。当任务跨越多个会话时，代理会丢失前序会话的上下文，导致其无法理解当前项目的状态。常见的失败模式包括：
* **过度贪婪**：代理试图在单个窗口内完成整个项目，导致上下文耗尽，产出半成品。
* **过早终止**：代理在项目后期误判任务已完成，导致后续迭代无法进行。

### 2. 双重代理架构
为了解决上述问题，框架引入了明确的角色分工：
* **初始化代理（Initialization Agent）**：在项目启动阶段，负责设置环境，包括创建 `init.sh` 脚本、初始化 Git 仓库，以及生成包含所有功能需求（标记为“失败”状态）的 JSON 进度文件。
* **编码代理（Coding Agent）**：在后续会话中，负责根据进度文件进行增量开发。它被要求一次只处理一个功能，并在会话结束时将代码库恢复至“干净状态”（即无重大错误、文档齐全且已提交至 Git）。

### 3. 环境管理与测试机制
* **结构化进度追踪**：使用 JSON 格式记录功能列表，强制代理通过修改 `passes` 字段来推进任务，避免了 Markdown 格式可能带来的覆盖风险。
* **Git 作为状态记忆**：通过 Git 提交记录和进度摘要，使代理在进入新会话时能快速重构上下文，理解已完成与未完成的工作。
* **端到端测试**：引入 [[Puppeteer]] 等浏览器自动化工具，使代理能够像人类用户一样验证功能，从而识别仅靠代码审查无法发现的端到端错误。

该框架不仅提升了 [[长期运行代理]] 的可靠性，还通过模拟优秀软件工程师的工作流，显著增强了 [[Claude Agent SDK]] 在构建复杂 Web 应用时的生产力。
