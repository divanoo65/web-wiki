# 扩展托管智能体：将大脑与双手解耦

## 执行摘要
随着 AI 模型能力的提升，传统的智能体编排方案（Harness）往往因为预设了模型能力的局限性而变得过时。Anthropic 通过推出 Managed Agents 服务，借鉴操作系统虚拟化硬件的思路，将智能体的会话（Session）、编排器（Harness）和沙盒（Sandbox）进行解耦。这种架构设计不仅解决了早期“宠物式”容器部署带来的运维难题，还实现了基础设施与模型逻辑的独立演进，为构建更稳定、可扩展的长周期智能体提供了范式。

## 核心要点

### 1. 应对模型能力的快速迭代
在构建智能体时，开发者往往会为模型编写“护栏”或补丁（例如针对“上下文焦虑”的重置机制）。然而，随着模型（如从 Claude Sonnet 4.5 到 Opus 4.5）的进化，这些硬编码的假设往往会失效，甚至成为冗余的负担。Managed Agents 的核心目标是构建一套能够超越特定模型实现细节的通用接口，确保基础设施的稳定性，同时允许模型逻辑灵活演进。

### 2. 从“宠物”到“牲畜”的架构转型
早期实现中，Anthropic 将会话、编排器和沙盒打包在同一个容器中，这导致了“宠物式”运维困境：容器一旦故障，会话数据即丢失，且难以调试。这种紧耦合设计限制了系统的可扩展性，尤其是在需要连接外部私有云环境时。通过解耦，Anthropic 将智能体组件虚拟化，使得每个组件可以独立替换和扩展，不再依赖于单一的运行环境。

### 3. 借鉴操作系统的抽象设计
Managed Agents 采用了类似操作系统虚拟化硬件的抽象层。通过定义标准化的接口（如会话日志、工具调用路由、执行环境），系统实现了“大脑”（Claude 模型）与“双手”（执行代码、编辑文件的沙盒）的分离。这种设计使得底层基础设施的变更（如更换存储后端或计算环境）不会影响上层的智能体逻辑，从而实现了对“尚未构想出的程序”的兼容性支持。
