# 少样本提示 (Few-Shot Prompting)

### 概念定义
少样本提示（Few-Shot Prompting）是一种提示词工程技术，旨在通过向大语言模型（LLM）提供少量具体的输入-输出示例，从而引导模型理解任务的意图、格式要求或特定的输出风格。与“零样本提示”（Zero-Shot Prompting）不同，少样本提示不依赖模型预训练阶段的通用知识，而是通过上下文学习（In-Context Learning）机制，让模型在当前会话中快速适应特定的模式。这种方法在处理主观性较强（如前端设计审美）或逻辑严密的任务时尤为有效，能够显著降低模型产生幻觉的概率，并提升输出结果的一致性与可预测性。

### 技术细节
少样本提示的核心在于“示例的选择”与“上下文的构建”：
1. **示例质量**：提供的示例必须具有代表性，涵盖任务中可能出现的边界情况。
2. **结构化呈现**：通常采用“输入-输出”对的形式，通过清晰的分隔符（如 Markdown 标题、XML 标签）将示例与实际任务区分开。
3. **上下文窗口利用**：在长周期应用开发中，少样本提示常与结构化制品（Artifacts）结合使用，通过在会话历史中注入高质量的示例片段，帮助代理（Agent）维持长期的任务一致性。
4. **动态调整**：在多代理架构中，评估器代理可以根据生成器代理的输出表现，动态调整提示词中的示例库，从而实现迭代优化。

### 应用场景
* **前端设计生成**：通过提供一系列高质量的 UI 设计代码片段作为示例，引导模型生成符合特定设计语言（Design System）的界面。
* **长周期自主编码**：在将复杂任务分解为可处理的块时，利用少样本提示为每个子任务提供标准化的代码实现范式，确保生成的全栈应用程序在不同模块间保持架构一致性。
* **主观评估标准化**：将模糊的审美标准转化为具体的评分示例，帮助评估器代理更客观地判断生成内容的质量。
