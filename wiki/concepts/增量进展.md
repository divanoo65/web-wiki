# 增量进展 (Incremental Progress)

### 概念定义
增量进展是针对长期运行的 AI 代理（Agent）在处理复杂任务时所面临的“上下文遗忘”与“任务中断”问题而提出的核心设计范式。在传统的代理交互中，由于上下文窗口的限制，模型往往倾向于在单一会话中尝试完成所有工作，导致任务在未完成时因上下文耗尽而中断，或在后续会话中因缺乏明确的进度记录而陷入混乱。增量进展要求代理在每个编码会话中，不仅要执行具体的编码任务，还必须负责生成清晰的、可供下一个会话读取的“产物”（Artifacts）和状态记录。这种方法将大型项目拆解为一系列微小的、可验证的步骤，确保代理在跨会话切换时能够无缝衔接，从而实现从原型到生产级应用的持续构建。

### 技术细节
实现增量进展的关键在于将代理的角色进行功能性拆解，并建立严谨的会话切换机制：

1.  **角色分工**：通过引入 [[初始化代理]]（负责环境搭建与初始状态配置）和 [[编码代理]]（负责具体的逻辑实现与进度推进），确保每个阶段的职责明确。
2.  **产物导向**：编码代理在会话结束前，必须生成包含当前进度、待办事项及环境状态的文档。这些文档作为“接力棒”，在下一个会话开始时被重新加载，从而弥补模型对上一班工作内容的记忆缺失。
3.  **防止“一键完成”倾向**：通过提示词工程（Prompt Engineering）限制代理的单次执行范围，强制其在有限的上下文内完成一个原子化的功能点，而非试图一次性构建整个应用。
4.  **状态压缩与传递**：利用 [[Claude Agent SDK]] 的上下文管理功能，将增量进展的记录进行压缩，确保关键的进度信息能够跨越上下文边界传递。

### 应用场景
*   **复杂 Web 应用开发**：在构建如“Claude.ai 克隆版”等大型项目时，利用增量进展将功能模块（如认证、UI 渲染、API 集成）分批次实现。
*   **长期维护的自动化脚本**：在需要持续运行并根据反馈调整的自动化任务中，通过增量进展记录历史执行结果，避免重复劳动。
*   **跨会话的复杂重构任务**：当代码库规模庞大，无法一次性加载到上下文时，通过增量进展逐步完成模块化重构，并确保每一步都有明确的测试覆盖。
