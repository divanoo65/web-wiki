# 上下文重置 (Context Resets)

## 概念定义
上下文重置（Context Resets）是一种在长周期智能体（Long-running Agents）运行框架中采用的防御性编程策略。其核心逻辑在于应对大语言模型（如 Claude Sonnet 4.5）在处理长任务时可能出现的“上下文焦虑”（Context Anxiety）。当模型感知到当前的上下文窗口即将达到上限时，可能会产生误判，从而过早地结束任务或截断输出。通过在工作框架（Harness）中显式地引入上下文重置机制，开发者可以强制模型在特定节点清理历史记录或重新初始化会话状态，从而确保任务能够跨越单一上下文窗口的限制，持续稳定地执行下去。这一机制本质上是一种对模型局限性的补偿，旨在通过外部控制手段维持智能体的长期运行能力。

## 技术细节
上下文重置的实现通常依赖于智能体框架（Harness）对会话日志（Session Log）的精细化管理。其技术要点包括：

1.  **触发机制**：框架会监控当前上下文的使用量或模型的行为模式。当检测到接近阈值或模型表现出“焦虑”迹象时，触发重置逻辑。
2.  **状态持久化**：在重置发生前，框架必须提取并保存当前任务的关键状态（如已完成的步骤、中间变量、文件系统状态），确保重置后的新会话能够无缝衔接。
3.  **会话初始化**：重置过程会清空旧的上下文窗口，并向模型注入经过压缩或总结后的“任务状态快照”，使模型在新的上下文中恢复工作，而无需重新处理冗长的历史交互。
4.  **动态演进**：随着模型上下文窗口的扩大或推理能力的提升，上下文重置可能变得多余。因此，该机制通常被设计为可插拔的模块，以便根据底层模型的特性进行启用或禁用。

## 应用场景
*   **长周期任务自动化**：在需要数小时甚至数天运行的复杂代码开发或数据分析任务中，防止模型因上下文溢出而中断。
*   **多阶段复杂工作流**：当任务被拆分为多个逻辑阶段时，利用上下文重置在阶段切换点清理无关历史，减少干扰并降低 Token 成本。
*   **模型性能调优与测试**：作为一种基准测试手段，用于评估不同模型版本（如 Claude Sonnet vs. Opus）对上下文限制的敏感度差异。

## 相关概念
*   [[上下文压缩]]：通过总结历史信息来减少 Token 占用，是上下文重置的补充手段。
*   [[上下文修剪]]：通过删除不重要的历史记录来维持窗口空间，与上下文重置共同构成了长周期智能体的内存管理策略。
